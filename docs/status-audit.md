## Gaps that remain supported by the evidence

- **Native SSH coordination:** local admission explicitly selects local jobs; the Run Now endpoint separately kicks the network queue. SSH is available through that older path. **spiped** remains excluded from GUI transport choices in [send helpers](../source/usr/local/emhttp/plugins/zfs.snapsync/php/send-helpers.php).
- **Independent shared cleanup authorization:** deletion tasks carry a single authorizing `ownerRunId`/`ownerItemId`. Multiple reference owners protect snapshots; they are not multiple independent authorizations to continue one shared deletion when an owner cancels.
- **Replanning after attempts/mutations:** [replanAuto](../source/usr/local/emhttp/plugins/zfs.snapsync/php/coordinator-state.php) accepts only eligible queued, never-attempted automatic work. [Auto admission](../source/usr/local/emhttp/plugins/zfs.snapsync/php/coordinator-auto-admission.php) rejects unsafe changes. “No replanning exists” is stale; general partial-execution replanning remains incomplete.
- **Auto Snapshot per-mutation tasks:** a coordinated attempt still invokes the existing `zfs_snapsync` worker through the logging wrapper. Run ownership, dataset gates, cancellation and captured configuration exist; every internal snapshot mutation is not yet represented as its own coordinator task.
- **Reboot continuity:** runtime history, review manifests and manual authority live in RAM. Explicit fresh recovery/review is available, but exactly-once execution across reboot and automatic reconstruction of lost manual authorization are not promised. This is also a safety boundary, not simply a missing Retry button.
- **Full release acceptance:** broad all-path flash-write, reboot/fault, scale/idle and host validation remain documented release gates. Existing fixtures provide scoped evidence, not proof that every gate is complete. This audit does not independently declare those gates passed or failed.

## How historical documents are treated

The implementation record and reliability audit are chronological evidence. Their old branch names, original-plugin paths, “not published,” and “still unfinished” statements describe their milestones. They are preserved with a prominent historical notice, not silently rewritten as if the later implementation existed then. The standalone roadmap and UI guide are current-facing documents and have been corrected. Earlier workflow and shutdown proposals now link to their replacements.

The installed Help/footer wording “full replication coordination remains unfinished” is broad but not demonstrably false: SSH and shared cleanup still prevent full coordination. The README now names the supported local recovery and specific remaining boundaries rather than saying only “some recovery integration.” No production behavior or release package is changed by this documentation audit.
